Azure-VMSS-Web-Multi-Region-MultiAZ

Overview

  • Terraform project provisions a highly available static website on Microsoft Azure.
  • Automatically deploys a scalable, fault-tolerant web infrastructure that serves content from GitHub.
  • Fully modular Terraform design separating networking, compute, and load balancing components.
  • Reusable and cost effective—supports rapid deployment across regions, zones, and subscriptions.
  • Multi-region deployment using Azure paired regions for increased resilience and disaster recovery.
  • VM Scale Sets distributed across Availability Zones where supported for zone-level fault tolerance.
  • Website updates deployed automatically through GitHub Actions on each push to the main branch.
  • Configuration ensures Linux VMs are kept up to date with system and package updates during provisioning.

Features

  • Creates dedicated Azure Resource Group to isolate deployed resources.
  • Deploys Azure Virtual Networks and subnets per region for secure, scalable networking.
  • Implements Azure Load Balancer with public frontend IP and backend pool for high availability.
  • Provisions VM Scale Sets across regions for horizontal scalability.
  • Distributes VM instances across Availability Zones where supported.
  • Installs and configures Apache and Git on each Linux VM during provisioning.
  • Clones static website content from GitHub during VM bootstrap using cloud-init.
  • Maintains VM instances up to date during provisioning.
  • Separates infrastructure deployment from application updates to avoid unnecessary redeployments.
  • Uses GitHub Actions to deploy updated website content across VMSS instances on each push.
  • Executes updates using Azure VMSS Run Command—no SSH or public IP required.
  • Supports dynamic discovery of VM Scale Sets within a Resource Group.
  • Designed to scale to large numbers of VMSS without extra GitHub secrets or Terraform state access.
  • Outputs key deployment details like resource group, VMSS IDs, load balancer backend pool IDs, and public IPs.

CI/CD Workflows Overview

Multiple GitHub Actions workflows securely manage Terraform infrastructure, backend state, security scanning, and deployment validation across environments. Workflows are chained to ensure safe, controlled infrastructure changes with PR requests.

CI/CD Pipeline Overview

├── Automation & CI/CD
│   ├── GitHub Actions Workflows
│   │   ├── Static Code Analysis
│   │   │   ├── TFLint
│   │   │   ├── Checkov
│   │   │   └── Terraform format & validation
│   │   ├── Terraform Plan Validation
│   │   ├── Backend State Validation
│   │   ├── Backend Bootstrap (Conditional)
│   │   ├── Terraform Apply (Controlled)
│   │   └── Website Content Deployment
│   └── Update Script (update_site.sh)

1. Static Analysis & Security Checks (Terraform + TFLint + Checkov)

  • Terraform Validation:
    • terraform fmt for consistent formatting
    • terraform validate to check syntax and configuration correctness
  • TFLint:
    • Scans Terraform code for best-practice violations and deprecated resources
    • Identifies inefficient or unsafe configurations
    • Enforces Azure-specific rules
  • Checkov:
    • Detects insecure resource configurations
    • Enforces policy compliance
    • Checks for missing encryption, logging, and access controls

If checks fail, the pipeline stops immediately. Only passing pipelines trigger the Plan Validation workflow.

2. Plan Validation Workflow

  • Detects target environment based on branch (dev, staging, main)
  • Loads environment-specific variables
  • Initializes Terraform with remote backend state
  • Runs terraform plan to validate changes before deployment

3. Backend Check Workflow

Validates Terraform backend configuration before infrastructure changes.

  • Detect target environment from branch or inputs
  • Configure backend using Resource Group, Storage Account, Container, and State file key
  • Check backend existence and accessibility
  • If missing, triggers Backend Bootstrap workflow

4. Backend Bootstrap Workflow

  • Creates Terraform backend resources (Resource Group, Storage Account, Blob Container)
  • Assigns correct RBAC
  • Creates Event Hub & Monitoring
  • Migrates local state to remote backend
  • Supports multiple environments using separate state files

5. Infrastructure Deployment Workflow

  • Terraform initializes using correct remote state
  • Environment-specific variables loaded dynamically
  • Applies infrastructure using terraform apply

6. Website Changes Workflow

  • Initial content deployed via cloud-init during VM provisioning
  • Triggered on pushes to main branch (Static Site directory)
  • Subsequent updates handled independently using GitHub Actions
  • Authenticates to Azure using a Service Principal
  • Dynamically discovers all VM Scale Sets in the target Resource Group.
  • Executes a shell script on each VMSS using az vmss run-command invoke.
    • Updates all VMSS instances automatically without SSH or public IP access

Infrastructure Details

  • Load Balancer distributes web traffic evenly across all VM instances.
  • Each VM runs Apache and serves content from the GitHub repository.
  • When a change is pushed to the GitHub repository, a GitHub Action automatically deploys the latest version of the site to all running VMs.
  • VM Scale Set ensures scalability and high availability across multiple zones.

Automated Website Update Flow

  • Terraform provisions the VMSS and installs Apache and Git using cloud-init.
  • Initial website content is cloned from GitHub during VM creation.
  • GitHub Actions workflow is triggered on every push to the main branch.

Each VM Performs

  • Pulls the latest version of the repository.
  • Copies updated static site files into the Apache web root.
  • Restarts Apache to serve the new content.

Deployment Instructions

  1. Clone this repository: 
    git clone https://github.com/Jammy-1/Mastering-Cloud
cd Mastering-Cloud/1.Projects/Azure-VMSS-Web-Multi-Region-MultiAZ/
  2. Configure Terraform variables: 
    resource_group_name = "rg-static-website"
location = "UK South"
github_repo = "https://github.com/your-org/your-repo"
github_branch = "main"
vm_admin_username = "azureuser"
ssh_public_key_path = "~/.ssh/id_rsa.pub"
instance_count = 2
vm_size = "Standard_B2s"

    Only public repositories are supported for this configuration.

  3. Initialize Terraform: 
    terraform init
  4. Preview the deployment plan: 
    terraform plan
  5. Deploy the infrastructure: 
    terraform apply
  6. Access your website: 
    terraform output public_ip

    Open http://<public_ip> in your browser to view the site.

Outputs

  • resource_group_name – Name of the deployed Resource Group
  • vmss_id – The ID of the Virtual Machine Scale Set
  • backend_address_pool_id – The Load Balancer backend pool ID
  • public_ip – The public IP address of the Load Balancer
